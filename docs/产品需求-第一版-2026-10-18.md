# 产品需求：第一版

日期：2026-10-18
依据：`idea/docs/小说阅读app/` 下的两份调研和选型文档，`docs/技术选型与验证-2026-09-28.md`，以及已经归档的 add-blocking-bridge、add-rule-engine、add-js-runtime、add-app-shell 四个 change。

这份文档定第一版要做什么、做到什么程度算完成。每项功能的详细行为写在 `openspec/specs/` 里，由各个 change 补充；这里只定范围和验收标准。第一版的功能全部完成后，统一做真机测试，然后发布。

## 一、产品定位

一个开源、完全免费的小说阅读器，兼容 Legado（开源阅读 3.0）书源。用户自己导入书源，app 按书源规则从网站取书、在本机阅读。

- **用户**：已经在用 Legado 系书源的人，愿意自己找书源、自己装 APK 或自签 IPA。不面向大众。
- **形态**：只有社区版（带书源）。不上架任何应用市场，没有服务器，没有账号。
- **核心体验**：导入书源 → 搜书 → 加书架 → 读得舒服，书源兼容做到 Legado 的水平，阅读排版不输 Legado。

## 二、约束

这些是前提，不随版本变化：

1. **完全免费**：app 内没有广告、内购；仓库不开赞助，不运营任何收益渠道。
2. **不提供内容**：仓库和安装包里不预置任何书源、站点名或书源订阅地址；不建官方书源仓库、群或频道。README 写明免责声明。
3. **没有账号和服务器**：不做注册、登录、云同步。所有数据只存在本机，换设备靠用户自己导出导入（见「备份与恢复」，P2）。
4. **不做书源登录**：书源里的 `loginUrl`、`loginUi` 登录流程不做，需要登录的书源按「不支持」报错。书源 JS 里读写登录头、登录信息的 API 照常可用（已实现）。
5. **开源协议**：GPL-3.0。

## 五、明确不做（第一版）

- 账号、登录、云同步、任何服务器。
- 书源登录流程（`loginUrl`、`loginUi`）。
- 预置书源、书源推荐、书源社区。
- 广告、内购、打赏、赞助。
- 上架版（不带书源的版本）、本地书。
- Windows、Linux、32 位 ARM。
- 漫画、音频、视频类书源。

## 六、验收标准

第一版完成的标准：上面所有 P0 做完，并且满足下面这些条件。真机数字是 2026-10-27、28 在 Redmi Note 14 Pro（天玑 7300，12GB 内存，Android 15，120Hz）上测的，写在每一条后面；详细数据记在 openspec change prepare-release 的 tasks 第 6 组。

**功能**
- 每个 P0 功能都有对应的规格（`openspec/specs/`），规格里的场景都有自动化测试。
- 端到端走查（`app/integration_test/real_sources_test.dart`）在 Android、iOS、macOS 上都通过：3 个 A 类、3 个 C 类书源走完搜索、加书架、读两章、重启后继续、刷新书架。实测：Android 真机、iOS 模拟器、macOS 通过；iPhone 真机上的走查还没做。
- 走查和冒烟里失败的书源，逐个确认是网站的问题，不是引擎的问题。

**性能**（Android 中端真机）
- 冷启动到书架可操作：2 秒以内。实测：release 构建，书架 10 本，10 次中位数 527 毫秒，最大 575 毫秒。
- 打开已缓存的章节：300 毫秒以内。实测：1 小时连续阅读里 158 次，中位数 41.6 毫秒，最大 150.3 毫秒。
- 分页翻页不掉帧（60fps）。实测：没有完全达标。覆盖模式基本不掉帧；滑动、无动画模式每翻一页约掉一帧（新的一页在第一次画时才创建画笔）。用户 2026-10-28 决定不挡发布，见 [待优化-滑动和无动画翻页掉帧](待优化-滑动和无动画翻页掉帧-2026-10-28.md)。
- 2000 章的目录打开：1 秒以内。实测：profile 构建，阅读页打开目录中位数 88.6 毫秒，打开详情页 66.5 毫秒，详情页打开目录 46.0 毫秒。
- 随机 200 个书源搜一次：60 秒以内结束（2026-10-25 在 macOS 和两个模拟器上约 30 秒，原来约 150 秒）。真机上没有测：用户 2026-10-28 决定不做，所以手机网络下同时 32 个连接的表现也没有测，上限保持 32。

**体积与稳定性**
- Android 单个 ABI 的 APK：20MB 以内。实测：10.9MB（2026-11-04 用 `tool/release.sh` 打的 0.1.0）。
- 连续阅读 1 小时（自动翻页或脚本翻页），不崩溃，内存不持续增长。实测：profile 构建，脚本翻页和跳章 1 小时没有崩溃；Dart 堆和排版对象不累积；原生内存涨了约 41MB，30 分钟只开关菜单的对照组涨得一样多，和阅读器无关。
- 书源出错（规则错误、JS 死循环、网络超时）只影响这个书源，不卡界面，不崩溃。
