## 一、结论

**纯 Flutter 项目。** 规则引擎用 Dart 写；书源里的 JS 交给自己绑定的 quickjs-ng 执行，放在后台 isolate 里跑；需要等网络、WebView 或用户输入的宿主函数，通过「工作 isolate 阻塞 + 主 isolate 异步处理 + Mailbox 唤醒」实现同步语义。

前置验证已在 macOS、Android 16 模拟器、iOS 26 模拟器上全部通过，结果见第三节。

## 二、为什么这样选

### 2.1 书源 JS 的「同步」到底要求什么

Legado 书源写的是 `var html = java.ajax(url)`，JS 会停下来等结果。复核读了 MD3 源码后确认：这是在要求 **JS 所在的线程能停住、再被唤醒**，而不是要求 HTTP 库本身同步。MD3 用 `runBlocking` 和 `LockSupport.parkNanos` 实现，等待的对象有三种（网络、WebView、用户输入），用的是同一个「停住 / 唤醒」原语。

所以选型要围绕这个原语来定，而不是围绕 HTTP 库。Dart 可以实现：工作 isolate 用 `Mailbox.take()` 阻塞自己所在的 OS 线程，主 isolate 用普通异步代码处理完请求后调用 `put()` 唤醒它。第一版文档里「Dart 做不到，所以要 Rust」的判断不成立。

### 2.2 稳定性门槛

门槛是：12 个月内有提交并且有发版；不止一个维护者，或者有组织背书；有生产项目在用。只剩个人 fork 在维护的，最高判「有风险」。

| 层 | 选用 | 判定 | 说明 |
|---|---|---|---|---|
| JS 引擎 | quickjs-ng v0.17.0，源码拷进本仓库，自写 C 胶水，Dart 绑定由官方 ffigen 生成 | 可用 | 现成的 Flutter QuickJS 插件**没有一个**过门槛：ekibun 版和 venera 版已停更；kodjodevf 版只有一人维护，还有每次调用泄漏的问题；flutter_js 在 Android 和 iOS 上跑的是两套不同引擎；fjs 只支持异步 |
| 阻塞原语 | `native_synchronization` 0.3.1，拷进本仓库自己维护 | 上游不达标，改为自持 | dart-lang/labs 的实验包，2024-09 之后再无发版。代码约 16KB，是纯 Dart 写的 FFI（pthread / WinAPI） |

Rust 路线（rquickjs + reqwest + scraper + flutter_rust_bridge）也每一层都能过门槛，但它有三个问题：WebView 和验证码在 Flutter 侧，需要跨边界阻塞等待；Cookie 要两边同步；还要引入第二种语言。纯 Flutter 需要自己维护的部分只有 C 胶水（约 300 行）和两个拷进来的小包，所以选纯 Flutter。

引擎单元测试（开发机，`dart test`）14 项全部通过：JSON 往返、同步宿主调用、嵌套求值、宿主异常转成 JS 异常、超时中断、内存上限、语法错误、2 万次连续调用，以及外部中止信号的 6 个场景。阻塞桥单元测试 33 项全部通过。

### 验证中发现并修复的问题

**线程迁移导致的栈溢出误报。** 在并发和压力场景下，偶发「Maximum call stack size exceeded」。原因是：Dart isolate 在两次事件之间可能被调度到另一个 OS 线程，而 QuickJS 的栈溢出检查还在用旧线程的栈顶地址。修复方法是在每个从 Dart 进入的最外层入口（注册宿主函数、设置全局变量、求值）按当前线程重算栈顶（`JS_UpdateStackTop`）；嵌套调用仍在同一线程上，不需要重算。修复后三个平台连续多轮稳定通过。

**所有现成插件都没有处理这个问题，这也说明了自持绑定层的价值。**

**立即 kill 正在宿主回调里的 worker，会让整个进程崩溃。**（2026-10-08）worker 在 JS 调用的 Dart 宿主函数里时（栈上夹着 QuickJS 的 C 帧），`Isolate.kill(priority: immediate)` 会让进程 `SIGSEGV`。纯 Dart 最小用例和 macOS spike 都复现了。所以阻塞桥的所有路径都不用立即 kill：取消和关闭池时，先写中止标志让 JS 退出，再 `kill(beforeNextEvent)`；宽限期内停不下来的 worker 直接放弃，补一个新的。

**在 Dart 里循环读共享内存标志，读取会被外提到循环外。**（2026-10-08）`while (!isCancelled) {}` 被内联后，JIT 把 `Pointer` 读取提到了循环外，永远读不到取消。给读取函数加 `@pragma('vm:never-inline')` 后，JIT 和 AOT 下都正常。

### 没有验证到的部分

- 真机：Android 64 位真机的 AOT 构建已验证（2026-10-11），C 类书源那一项（2026-10-13）还没在真机上跑；iOS 真机还没跑。真机测试在所有功能开发完成后统一做。不支持 32 位 ARM（armv7）设备（2026-10-11 决定），不做验证。
- 真实的 WebView：只用延迟模拟了「主 isolate 异步等待」。实际接入 WebView 时，要确认它在主 isolate 上加载页面、拿到结果后，走的是同一条 Mailbox 通道。
- 内存泄漏：跑了 2 万次调用没有崩溃；真机上测了 worker 的 RSS（见上），但只跑了两轮负载，没有做长时间的 RSS 曲线，泄漏还不能排除。

### 书源 JS 冒烟（2026-10-13）

JS 运行时（change add-js-runtime）完成后，用同一个工具、同一份书源和搜索词，按 source-check 的分级各随机取 200 个 B 类（有 JS、不调宿主 API）和 C 类（调宿主 API）书源（种子 1）。排查修复后又跑了一遍：

| 批次 | 搜索 | 详情 | 目录 | 正文 |
|---|---|---|---|---|
| B 类 200 条，第一遍 | 46 | 45 | 37 | 34 |
| B 类 200 条，修复后 | 45 | 44 | 40 | 39 |
| C 类 200 条，第一遍 | 52 | 49 | 42 | 36 |
| C 类 200 条，修复后 | 54 | 50 | 40 | 30 |

两遍之间的差别都能对上：B 类多出的 5 条是下面修复的引擎问题；C 类少掉的 6 条是站点变了（塔读 4 条开始返回腾讯验证码页，小米阅读 2 条的接口返回 404），用 curl 和录制的响应核对过。

修复后搜索没通过的主要是站点本身：搜索无结果（B 71、C 75）、网络错误和 TLS 握手失败（B 52、C 45）、没有搜索地址（B 26）。JS 错误、目录为空、正文为空、JSONPath 取不到值这几类逐个看过录制的响应：

- 引擎问题，已修复并补了用例：
  - jsoup 的 `hasClass` 在 class 属性和要找的名字一样长时整体比较，`class.a b` 能匹配 `class="a b"`，原来按空白切开比较（若初文学 3 条、经致文学）；
  - JSONPath 的 `$.[*]`（点后面紧跟方括号）不认（米读）；
  - 规则末尾的 `{$.x}` 取不到值时位置越过字符串末尾，Dart 抛 RangeError，Java 只是返回 -1（漫客栈、快读小说等 4 条）；
  - JSONPath 取到的对象在 MD3 里是 Java Map，书源用 `String(result).match(/id=(\d+)/)` 取字段，原来得到的是 `[object Object]`（猫耳 FM 3 条）；
  - 目录链路更新的书籍（章节数、当前章节名、JS 写入的变量）在 worker 里是副本，没有交回，正文 JS 读 `book.totalChapterNum` 失败（爱优漫）；
  - 元素列表缺 `hasClass` 等 jsoup `Elements` 方法。
- 不是引擎的问题：网站返回验证页、403、WAF、跳转到停放域名或首页、接口报「认证失败」「参数错误」「黑名单」、章节内容不可用；文件类书源没有下载地址规则（MD3 同样报「下载链接为空」）；4 条在 JS 里用了 `org.jsoup`、`JavaImporter`（Java 互操作，source-check 没有识别出来，实际属于 D 类）；1 条调用了 `java.startBrowserAwait`、1 条调用了 `java.getVerificationCode`（不支持的宿主 API，按规格报错）；起点系的 7 条搜索时就拿到了反爬页（202 加 probe.js）。

跑通的书源里录了 6 个固定样例（规则 JS、URL 里的 JS、`java.ajax`、`java.put/get`、`java.getString`、`java.base64Decode`、`java.timeFormat`），不联网重放。用到加解密的两个书源在请求地址里带当前时间和签名，无法重放；跑通的书源里没有用到 jsLib、`formatJs`、`loginCheckJs` 的，这几项由单元测试覆盖。

性能：2000 章的目录，章节名和地址都带 JS 时目录链路约 210 ms，再加 `formatJs` 约 260 ms（macOS，Apple M4）；单次隔离求值约 20 µs。

### app 外壳走查（2026-10-18）

app 外壳（change add-app-shell）完成后，用 `app/integration_test/real_sources_test.dart` 在 macOS 和 iOS 26 模拟器（debug 构建）上联网走查，书源文件经「从网址导入」载入，搜索词「斗罗大陆」。

- **worker 数的硬上限是 6**：同一个 isolate group 里同时运行的 isolate 最多 8 个（Dart VM 的 `MaxMutatorThreadCount`，16MB 新生代 / 512KB TLAB / 4，与核数无关），阻塞在 `Mailbox.take()` 里的 worker 也占一个。超过之后主 isolate 每处理一条消息都要等 120ms 抢占，越多越慢，最后卡死。走查时把池调到 16，iOS 模拟器上搜到一半卡死（主线程停在 `IsolateGroup::IncreaseMutatorCount`），之后压测：N 个 worker 在 JS 里反复阻塞调用，6 个 1.6 秒、8 个 9 秒、12 个 19 秒、16 个卡死，macOS 和 iOS 模拟器一致；只阻塞一次时 12 个也能完成，所以第三节的压测没有发现。第一节说「内存不是 worker 数的约束」仍然成立，约束在这里。app 里 worker 数 = 8 − 主 isolate − drift 的后台 isolate = 6，批量任务（搜索、书架更新）同时最多 4 个。
- 搜索计时：aoaostar/legado 当前的全量书源（3907 条）里有搜索地址的文本类 3024 条，随机取 200 条（种子 1），去重后 192 个，macOS 144 秒、iOS 模拟器 151 秒。有结果的书源约 120 个；失败的约 70 个以网络错误为主（约 57），其余是需要 WebView 6、JS 错误 5、规则错误 3。时间主要花在慢站点等到超时上，要再快应该缩短搜索的超时，而不是加 worker。
- 走查：rule_engine 录制样例里的 6 个书源（A 类：必读居、抖音小说、不知加啥；C 类：多看阅读、得间小说、影书小说）各走一遍详情 → 加入书架 → 读第一、二章，全部通过；然后关闭数据库、用同一个文件重新启动，书架上 6 本书都在、进度都是第 2 章，从书架打开回到上次的章节（读缓存）；刷新书架 6 本约 37 秒，没有失败。macOS 和 iOS 模拟器结果一致。
- 走查中发现并修复了两个界面问题：章节很短时点正文中部打不开阅读菜单（手势区域没有铺满整页）；阅读菜单的返回按钮被目录抽屉的按钮顶掉。
- 封面请求不带书源请求头，部分站点的封面 404，显示占位（MD3 会带请求头，留到以后）。

### Android 工程（2026-10-18）

app 加上 Android 平台（change add-android）后，在 Android 16 模拟器（arm64，debug 构建）上重跑：

- 单元测试、widget 测试和平台无关，在开发机上跑；端到端集成测试（`app_flow_test.dart`）在模拟器上通过，模拟器息屏时开始也能通过（debug 构建启动时点亮屏幕、显示在锁屏之上、运行期间不息屏，release 包没有）。
- 真实书源走查：书源文件经开发机的本地 HTTP 服务器、用 `http://10.0.2.2:8765/` 导入。6 个书源全部通过，重启后书架 6 本、进度都在第 2 章，刷新书架约 37 秒没有失败，和 macOS、iOS 一致。192 个书源搜一次 147 秒（macOS 144 秒、iOS 模拟器 151 秒），失败的类别和数量相近（网络错误 60，其余需要 WebView 6、JS 错误 5、规则错误 3）。
- 包体积：`flutter build apk --release --split-per-abi --target-platform android-arm64` 只出 `app-arm64-v8a-release.apk` 一个包，10.1MB，PRD 的目标是 20MB 以内。压缩后最大的几项：Flutter 引擎 `libflutter.so` 5.2MB，Dart AOT 代码 `libapp.so` 3.2MB（解压后 8MB，其中 Flutter 框架约 3MB、rule_engine 约 850KB、html 解析约 240KB、app 自己约 210KB），`libsqlite3.so` 0.8MB，`libquickjs_ng_ffi.so` 0.5MB，`classes.dex` 0.2MB。不拆包时插件的原生库会带上 armeabi-v7a、x86、x86_64（`--target-platform` 只管 Flutter 引擎），包变成 13.2MB，所以发布必须按 ABI 拆包。
- 发现并修复的问题：Android 上 file_selector 只按 MIME 过滤，下载来的书源文件常被识别成 `application/octet-stream` 而选不了，Android 上改成列出 MIME 类型（不能加到所有平台共用的过滤条件里：macOS 会把 `application/octet-stream` 换成 `public.data`，放开所有文件）；Android 上选中的文件是内存字节，cross_file 对它的 `readAsString` 按 Latin-1 解码，中文书源名变成乱码，改成和从网址导入一样自己按 UTF-8 解码；阅读页暗主题下状态栏图标仍是深色、看不清（iOS 也一样），改成按正文背景色决定。
- release 包的网络权限要写在 main manifest 里（Flutter 模板只在 debug、profile 里有）；插件都声明 NDK 27，模板默认的 26.3 会告警，固定成 27.0.12077973。
