## 网站造成的字段不同（不是问题）

- 正文里每次不同的随机数字（无极书院、五八书阁）、随机插入的防盗文字（米读小说、独行小说）。
- 搜索每次返回不同的书（飘天文学、飘天文学手机版），之后的详情、目录、正文都跟着不同。
- 每日内容不同（一个阅读）。
- 地址里的签名和时间戳（阅友网络）。

## 对比口径

试跑时发现的假差异都按 MD3 的代码处理掉了（详见 change add-md3-diff 的设计 D4）：
- 详情的日志是每条规则取到的值，按 MD3 `BookInfo` 的赋值规则还原成书的最终值。
- 搜索记的是列表第 0 项，它被丢掉时不比较。
- 目录的「首章信息」是倒序和去重之前的，不比较；用的是哪一章看正文这一步的章节名。
- 封面的相对地址、地址里每次都变的查询参数值不算不同。

## 建议的修复顺序

1. 第 3、4、5、6 条：都是引擎里的具体缺口，改动小、规则明确，可以放在一个改动里修。
2. 第 2 条：先支持经 `java` 对象访问的 `java.lang.String`、`java.security.MessageDigest` 等最常见的几个类，再看剩下的。
3. 第 1 条：要在 Android 上换用系统的网络栈（如 OkHttp 或 Cronet），iOS 上用 NSURLSession，影响面大，单独评估。
4. 第 7 到 11 条：逐个查清原因后再决定。
