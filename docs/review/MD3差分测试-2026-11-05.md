## 网站造成的字段不同（不是问题）

- 正文里每次不同的随机数字（无极书院、五八书阁）、随机插入的防盗文字（米读小说、独行小说）。
- 搜索每次返回不同的书（飘天文学、飘天文学手机版），之后的详情、目录、正文都跟着不同。
- 每日内容不同（一个阅读）。
- 地址里的签名和时间戳（阅友网络）。

## 对比口径

试跑时发现的假差异都按 MD3 的代码处理掉了（详见 change add-md3-diff 的设计 D4）：
- 详情的日志是每条规则取到的值，按 MD3 `BookInfo` 的赋值规则还原成书的最终值。
- 搜索记的是列表第 0 项，它被丢掉时不比较。
- 目录的「首章信息」是倒序和去重之前的，不比较；用的是哪一章看正文这一步的章节名。
- 封面的相对地址、地址里每次都变的查询参数值不算不同。

## 2026-11-06：Java 字符串与摘要兼容

MD3 的 `SharedJsScope` 用空 bindings 执行 jsLib，`AnalyzeRule` 只在本次规则 bindings 注入 `java=this`。因此 jsLib 函数中的词法 `java` 是 Java 包，函数的 `this.java` 才是调用方宿主；不能把 `lang/security` 直接加到三种宿主对象上。本次在全局补包入口，规则需要 Java 类时使用 `Packages.java…`，原有宿主接口保持原语义。目录 `formatJs` 同样能访问全局包，但没有注入宿主 `java`。

`String` 支持文本/字节构造、`getBytes` 和文本转换；`MessageDigest` 支持现有摘要算法、增量更新、指定字节范围、摘要后重置。原生 JS 字符串不增加 Java 方法。测试使用 `test/fixtures/kugou_java_source.json` 中的原始 jsLib 和搜索规则，只冻结时间；MD5 搜索签名与独立计算结果一致，并验证作用域、字节符号、状态隔离及跨任务实例。

联网复测同一合集、同一关键词「三界红包群」：搜索 1 本，书名《三界红包群》，作者小教主；目录 4894 章，首章「第0001章 抢到三根毛」，正文 2785 字，四链路均通过。书名、作者、目录数和首章名与原 MD3 记录一致。本次未启动 MD3 服务重跑双端差分，不更新上方原批次统计。

## 2026-11-06：响应构造与实体解码

`StrResponse(url, body)` 支持直接调用与 `new`，返回链路接受的响应对象，保留可空正文，默认 200/OK、空响应头和非重定向状态，不继承原响应的元数据。有效 URL 处理使用现有 Dart URI 能力，非 HTTP(S) 或非法地址回退 localhost；完整 OkHttp URL 规范化不在本批范围，已在引擎 README 记录差异。

`Parser.unescapeEntities` 按 jsoup 1.16.2 独立扫描实体，复用现有 HTML5 数据表，覆盖缺分号、属性模式、多码点实体、非法数字、NUL 和 Windows-1252 映射；不解析标签或改换行。26 项边界用例由 JAR oracle 生成，另有 31,234 个实体组合对照零差异。新增真实点众/聚合登录检查脚本及格格党原始规则的离线回归。

## 2026-11-06：雨鹿字节流与列表

新增 Java 包中的 `ByteArrayOutputStream` 和 `ArrayList` 有限兼容。流按低八位写入、返回有符号字节，数组写入与输出快照均复制容器；`close()` 无副作用，`reset()` 清空。列表按序保存对象，允许 null 和重复元素，跨 JS/Dart 边界保留字段，供原始搜索与目录规则取值。实例状态在 JS 内保存，jsLib 缓存跨任务不会持有失效的宿主句柄。

离线回归直接使用雨鹿原始 jsLib 与四链路规则，合成配置、搜索、详情、站点源、站点正则的动态 AES 信封，以及目录标题和正文的固定 AES 响应，覆盖全部 256 个字节值、中文/补充平面字符、搜索去重、列表内嵌对象、源选择与正文净化；未修改原始脚本绕过兼容问题。另用 JDK 对照低八位写入、越界、关闭/重置和列表快照语义。
