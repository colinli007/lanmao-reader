## Purpose

替换净化规则：用户导入或自己编写的文本替换规则，兼容 Legado 的替换规则格式，用来去掉正文和章节名里的广告文字。这份规格规定规则的格式、怎样管理规则，以及规则怎样作用在一章上。

## ADDED Requirements

### Requirement: 规则的格式
系统 SHALL 读取 Legado 导出的替换规则 JSON：一个规则对象，或者规则对象的数组。每个字段的含义和缺省值如下：

| 字段 | 含义 | 缺省值 |
|---|---|---|
| `id` | 规则的标识，数字 | 导入时生成 |
| `name` | 名称 | 空 |
| `group` | 分组，只保存，不参与筛选 | 空 |
| `pattern` | 替换规则：正则或普通文本 | 必填 |
| `replacement` | 替换为 | 空 |
| `isRegex` | 是否正则 | 是 |
| `scope` | 作用范围 | 空 |
| `excludeScope` | 排除范围 | 空 |
| `scopeContent` | 作用于正文 | 是 |
| `scopeTitle` | 作用于章节名 | 否 |
| `isEnabled` | 启用 | 是 |
| `timeoutMillisecond` | 一次执行的超时时间，毫秒；不大于 0 时按 3000 | 3000 |
| `order` | 顺序，数字小的先执行 | -2147483648 |

下面这些项 SHALL 跳过，并说明原因：

- 不是对象。
- `pattern` 缺失或为空。
- 是正则，但无法编译；或者末尾是没有转义的 `|`（会匹配空串）。

规则对象里的其它字段 SHALL 原样保存，导出时带出。

#### Scenario: 缺省值
- **WHEN** 导入 `{"id": 1, "pattern": "请记住本站.*"}`
- **THEN** 得到一条启用的正则规则，替换为空，作用于正文，不作用于章节名，作用于所有书，超时 3 秒

#### Scenario: 无法编译的正则被跳过
- **WHEN** 导入的数组里有一条 `{"pattern": "[未闭合", "isRegex": true}`
- **THEN** 这一条被跳过，原因是正则无法编译；其它规则照常导入

### Requirement: 导入替换规则
用户 SHALL 可以从文件、网址、粘贴文本导入替换规则，方式和导入书源相同。写入前 SHALL 显示新增几条、更新几条、跳过几条和跳过的原因，用户确认后才写入。

- 同一个 `id` 在内容里出现多次时，以最后一次为准。
- `id` 和已有规则相同时，SHALL 用导入的内容更新这条规则，启用状态取导入内容里的 `isEnabled`。
- 内容不是 JSON，或者网址下载失败时，SHALL 显示原因，不写入。

#### Scenario: 再次导入同一份规则
- **WHEN** 用户导入一份 3 条规则的文件，停用其中一条，再导入同一份文件
- **THEN** 预览显示更新 3 条、新增 0 条；导入后仍是 3 条，被停用的那条按文件里的 `isEnabled` 恢复为启用

### Requirement: 规则列表
设置页的「替换净化规则」SHALL 打开规则列表：

- 按 `order` 从小到大排列，`order` 相同时按 `id` 从小到大。这也是执行的顺序。
- 每条显示名称；名称为空时显示替换规则。
- 每条有启用开关，改动立即生效并落盘。
- 没有规则时，SHALL 提示可以导入或新建。

#### Scenario: 停用一条规则
- **WHEN** 用户在列表里关掉「去本站广告」的开关，然后打开一个含「请记住本站域名」的章节
- **THEN** 正文里仍显示「请记住本站域名」

### Requirement: 新建和编辑规则
用户 SHALL 可以新建规则，也可以点列表里的一条进行编辑。可以编辑的项：名称、替换规则、替换为、是否正则、作用范围、排除范围、作用于正文、作用于章节名。

- 替换规则为空时，SHALL 不能保存。
- 是正则时，如果正则无法编译，或者末尾是没有转义的 `|`，SHALL 不能保存，并显示原因。
- 新建的规则启用，排在最后：`order` 比现有规则都大。
- 编辑时，不在表单里的字段（分组、超时时间、启用状态、其它字段）保持不变。
- 编辑页 SHALL 可以删除这条规则，删除前需要确认。

#### Scenario: 新建规则
- **WHEN** 用户新建规则，替换规则填「最新章节请到.*?阅读」，勾选正则，保存
- **THEN** 列表最后多出这条规则，已启用

#### Scenario: 正则写错
- **WHEN** 用户把替换规则改成 `(未闭合`，勾选正则，点保存
- **THEN** 不保存，显示正则无法编译

### Requirement: 导出替换规则
用户 SHALL 可以把全部规则导出到剪贴板。导出的是 JSON 数组，每条是导入时的原始内容加上编辑后的字段，`isEnabled` 为当前的启用状态。导出的内容 SHALL 能被本 app 和 Legado 重新导入。

#### Scenario: 导出后再导入
- **WHEN** 用户导出 3 条规则，删除全部规则，再粘贴导出的文本导入
- **THEN** 得到同样的 3 条规则，启用状态和顺序都和导出前一样

### Requirement: 规则的作用范围
一条规则对一本书生效，SHALL 同时满足：

- 规则已启用。
- 作用范围为空，或者作用范围的文字里包含这本书的书名，或者包含这本书的书源地址。
- 排除范围为空，或者排除范围的文字里既不包含书名，也不包含书源地址。

作用于正文的规则替换正文，作用于章节名的规则替换章节名；两项都没勾选的规则不起作用。

#### Scenario: 只作用于某本书
- **WHEN** 规则的作用范围是「三体;球状闪电」，用户分别打开《三体》和《流浪地球》
- **THEN** 规则只替换《三体》的正文

#### Scenario: 排除某个书源
- **WHEN** 规则的作用范围为空，排除范围是书源 A 的地址
- **THEN** 来自书源 A 的书不替换，来自其它书源的书都替换

### Requirement: 执行替换
对一章执行替换时，系统 SHALL 按「规则列表」的顺序，把生效的规则依次作用在整章文字上，后一条作用在前一条的结果上：

- 正则规则：按 Java 正则语法匹配，替换全部匹配；替换为按 Java 语法解释（`$1` 引用分组，`\` 转义）。正则的语法和书源里的净化正则（rule-syntax「正则净化」）相同。
- 普通文本规则：把替换规则作为普通文字查找，替换全部出现的地方；替换为也按普通文字。
- 替换为不合法（比如引用了不存在的分组）时，这条规则不改变文字，继续执行下一条。

#### Scenario: 删除广告
- **WHEN** 正文里有一行「请记住本站域名 www.example.com」，规则是正则 `请记住本站.*`、替换为空
- **THEN** 这一行变成空行，排版时被丢弃

#### Scenario: 引用分组
- **WHEN** 正则是 `(\d+)章`，替换为 `第$1章`，正文是「共 12章」
- **THEN** 结果是「共 第12章」

#### Scenario: 普通文本里的特殊字符
- **WHEN** 普通文本规则的替换规则是 `(本章完)`，替换为 `$1`，正文里有「(本章完)」
- **THEN** 结果里这几个字换成 `$1` 两个字符

#### Scenario: 依次作用
- **WHEN** 第一条规则把「AB」换成「C」，第二条把「CD」换成「E」，正文是「ABD」
- **THEN** 结果是「E」

### Requirement: 超时停用
一条正则规则对一章执行的时间超过它的超时时间时，系统 SHALL：

- 中止这条规则，这一章按执行它之前的文字继续执行后面的规则。
- 停用这条规则并落盘。
- 告诉用户这条规则因为超时被停用（见 reader「替换净化」）。

一条规则超时 MUST NOT 让其它规则或者之后的阅读卡住。

#### Scenario: 灾难性回溯
- **WHEN** 一条启用的规则是正则 `(a+)+b`，超时 3 秒，正文里有一段 30 个 `a`
- **THEN** 大约 3 秒后这一章显示出来，这段 `a` 原样保留；规则列表里这条变成停用
