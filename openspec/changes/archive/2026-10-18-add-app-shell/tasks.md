## 3. 存储层

- [x] 3.1 drift 数据库和七张表（D2），后台 isolate 打开；书、章节、正文、设置的读写方法；书架的查询按 bookshelf 规格排序（最近阅读降序，未读过的按加入时间降序排在后面）。验证：用内存数据库的单测覆盖增删改查和排序。
- [x] 3.2 浏览中的书（D3）：`in_shelf` 标志，启动时清理所有不在书架上的书及其目录、正文；加入书架只改标志和 `added_at`；移出书架在一个事务里删书、目录、正文。验证：用文件数据库的单测：写入一本浏览中的书和一本书架上的书，关闭后重新打开并执行启动清理，只剩书架上的书；移出书架后三张表里都没有它的行。对应 app-storage「不在书架上的书」「移出书架时清理」的场景。
- [x] 3.3 落盘队列：串行执行写入，失败时交给书源日志（D4）；进入后台时等待队列清空。验证：单测里让一次写入抛错，后续写入照常执行，日志收到一条错误。
- [x] 3.4 `PersistentSourceStore`（D4）：启动时载入未过期的行并删除过期的，`get` 只读内存，`put` / `delete` 先改内存再入队，`putMemory` 等不落盘。验证：单测覆盖 app-storage「书源级状态读写即时可见」的三个场景（用可注入的时钟模拟过期，重开数据库模拟重启）；`putMemory` 的值重开后读不到。
- [x] 3.5 Cookie 落盘（D5）：启动时载入 `cookies` 表作为 `CookieStore` 的初始值，回调写入同一个队列。验证：单测覆盖 app-storage「持久 Cookie」的三个场景（本地 HTTP 服务器返回 Set-Cookie，重开数据库后新建 `RuleHost` 再请求，检查请求头）。

## 4. 引擎接入与书源管理（online/）

- [x] 4.1 启动流程（D1、D6）：打开数据库 → 启动清理 → 载入书源级状态和 Cookie → 建 `RuleHost`（`onLog` 接日志缓冲区）和大小 8 的 `WorkerPool` → `runApp`；批量任务的限流器（同时最多 6 个，可随 `CancelToken` 丢弃未提交的任务）。验证：限流器的单测：提交 20 个任务，池里同时不超过 6 个；取消后未提交的任务以取消错误结束、不再提交。
- [x] 4.2 引擎模型与 `library/` 模型的转换（D1）：`Book`、`BookChapter` 的引擎专用字段进出 `sourceData`；`BookContentSource` 的实现（目录、正文）。验证：单测：`Book` → 书架模型 → `Book` 往返后 `variables`、`tocUrl`、`reverseToc` 等字段不变；章节的 `baseUrl`、`variables` 往返不变。
- [x] 4.3 书源导入（D10）：文件、网址、粘贴文本三种来源；预览新增、更新、跳过；确认后写入，启用状态取 `enabled`。验证：widget 测试覆盖 source-management「导入书源」的三个场景；网址导入用本地 HTTP 服务器，404 时显示原因且不写入。
- [x] 4.4 书源列表：名字、地址、启用状态、非文本类型标记，按首次导入顺序，筛选；单个开关和多选批量启用、停用、删除（删除前确认）；导出到剪贴板（覆盖 `enabled`）。验证：widget 测试覆盖「书源列表」「启用与停用」「删除书源」「导出书源」的场景（「停用后书架照常」「删除后书架保留」在第 7、8 组的测试里验证）。
- [x] 4.5 书源日志（D11）：容量 500 的环形缓冲区，新的在前，显示时间、书源名（查不到时显示地址）、字段和内容，可清空。验证：单测覆盖「只保留 500 条」；widget 测试：经 `RuleHost.onLog` 送入一条日志后，日志页最上面是它。
