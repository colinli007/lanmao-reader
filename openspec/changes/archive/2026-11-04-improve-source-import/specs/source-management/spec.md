## MODIFIED Requirements

### Requirement: 导入书源
系统 SHALL 支持三种导入来源：用户选择的本地文件、网址（下载其内容）、粘贴的文本。内容按 Legado 书源 JSON 解析，可以是单个书源对象、书源数组，或网址列表 `{"sourceUrls":[…]}`（规则见 book-source）。写入前 SHALL 显示预览：新增几个、更新几个（书源地址已存在）、跳过的条目的位置和原因；用户确认后才写入，取消时不做任何改动。更新时用导入的内容整体替换原书源。启用状态取导入内容里的 `enabled` 字段，没有这个字段时为启用。

内容是书源对象或数组、但一个可用书源都没有时，MUST NOT 显示预览，SHALL 整份报错并显示原因，不写入任何书源：
- 每个条目都是订阅源：「这是订阅源，不是书源，暂不支持订阅源」
- 空数组：「内容里没有书源」
- 其它情况，包括内容不是合法 JSON：「不是书源。内容开头：」加上内容开头 100 个字符（按 Unicode 码点计，连续空白合并成一个空格，超出部分用「…」表示）

内容是网址列表时，系统 SHALL 下载列表里的每个网址，各自按书源 JSON 解析，合并成一次预览；同一个书源地址出现多次时以最后一次为准。只展开一层：下载到的内容又是网址列表时，按「内容里没有书源」处理。某个网址下载失败或其中没有可用书源时，SHALL 在跳过列表里写明这个网址和原因（原因同上），其它网址照常导入；网址内部被跳过的条目写明网址和它在数组里的位置。网址列表里的网址全部失败时仍显示预览，不能确认导入。

从网址下载时，网址以 `#requestWithoutUA` 结尾的，SHALL 去掉这个标记再请求，并且请求不带 User-Agent；其余请求带和书源请求相同的默认 User-Agent。网址下载失败时 MUST 显示原因，不写入任何书源。

#### Scenario: 预览新增、更新和跳过
- **WHEN** 已有书源 `https://a.com`，导入的数组里有 `https://a.com`、`https://b.com` 和一个没有 `bookSourceUrl` 的对象
- **THEN** 预览显示新增 1、更新 1、跳过 1（第 3 项，缺少书源地址）；确认后书源列表里是更新过的 `https://a.com` 和新的 `https://b.com`

#### Scenario: 不是书源 JSON
- **WHEN** 粘贴的文本是 `hello`
- **THEN** 显示「不是书源。内容开头：hello」，书源列表不变

#### Scenario: 下载到的是网站的错误信息
- **WHEN** 从网址导入，网站返回 HTTP 200 和 `{"msg":{"user_not_login":"用户未登录"},"code":1000}`
- **THEN** 不显示预览，显示「不是书源。内容开头：{"msg":{"user_not_login":"用户未登录"},"code":1000}」，书源列表不变

#### Scenario: 订阅源
- **WHEN** 导入的数组里只有 2 个订阅源（有 `sourceUrl`，没有 `bookSourceUrl`）
- **THEN** 显示「这是订阅源，不是书源，暂不支持订阅源」，书源列表不变

#### Scenario: 网址列表
- **WHEN** 导入 `{"sourceUrls":["<网址1>","<网址2>"]}`，网址 1 返回 2 个书源，网址 2 返回 404
- **THEN** 预览显示新增 2，跳过列表里有「<网址2>：下载失败：HTTP 404」

#### Scenario: 不带 User-Agent 下载
- **WHEN** 从网址 `https://a.com/s.json#requestWithoutUA` 导入
- **THEN** 请求的是 `https://a.com/s.json`，请求头里没有 User-Agent

#### Scenario: 导入时停用
- **WHEN** 导入的书源带有 `"enabled": false`
- **THEN** 导入后这个书源处于停用状态
