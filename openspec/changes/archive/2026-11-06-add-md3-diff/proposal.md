## Why

规则引擎的目标是行为和 legado-with-MD3 一致，但目前只能靠单元测试、录制样例和书源校验间接判断，书源校验只看「有没有结果」，看不出「结果对不对」。PRD 4.6 把「和 MD3 的批量差分测试」列为 P1：同一批书源、同一个关键词，两边各跑一遍，逐项对比，找出兼容问题。上一项 JS 兼容就是靠这类统计定下修什么的。

用户 2026-11-05 确认：用 MD3 官方 3.26.23（装在模拟器上）当对照，跑合集 1329 的 320 个书源。

## What Changes

- **对照方**：模拟器上的 MD3 打开 Web 服务，`/saveBookSources` 导入同一批书源，每个书源经 WebSocket `/bookSourceDebug` 跑一遍「书源调试」（搜索第一本 → 详情 → 目录 → 第一章正文），日志里有每一步取到的字段和错误。
- **我们**：新开发工具 `packages/rule_engine/tool/md3_diff.dart`，用规则引擎照同样的流程跑：同一个关键词、搜索结果的第一本、同样的跳过卷名规则、同样的「下一章地址」。
- **对比**：
  - 解析 MD3 的调试日志，和我们的结果一一对应。
  - 逐项比较：搜索结果数和第一本的书名、作者、地址，详情的各个字段，目录总数、第一章的名字和地址，正文的标题和内容（空白规范化之后）。
  - 每个书源归为：一致、只有我们失败、只有 MD3 失败、都失败、都成功但字段不同。
- **报告**：JSON（两边的原始结果和差异）和 Markdown 摘要（各类数量、按原因归类的失败、字段差异最多的项），留给后续逐类修复。
- **不做**：这次只出工具和第一份报告，不修报告里发现的问题（按出现次数另开改动）；不对比发现页、多页搜索。

## Capabilities

### New Capabilities

- `md3-diff`：和 MD3 的差分测试工具：对照方、流程、字段对比、分类和报告。

## Impact

- **packages/rule_engine/tool/**：新增 `md3_diff.dart` 和 `md3_diff/`（MD3 调试日志解析、对比、报告）。
- **packages/rule_engine/test/**：日志解析和对比的单元测试。
- **模拟器**：安装 MD3 3.26.23（包名 `io.legato.kazusa`），打开 Web 服务，`adb forward` 1122（HTTP）和 1123（WebSocket）。
- 不改 app 和规则引擎的代码。
