# source-check Specification

## Purpose
书源校验：用关键词依次检查书源的搜索、详情、目录、正文，把失效的书源标上分组和错误注释，方便用户批量清理。做法和 Legado 的 `CheckSourceService` 一样。

## Requirements

### Requirement: 发起校验
用户 SHALL 可以在书源列表的多选状态下校验选中的书源。开始前 SHALL 让用户确认关键词，默认是「我的」。书源的 `ruleSearch.checkKeyWord` 不为空、并且不含 `http`、`::`、`++`、`--` 时，这个书源用它自己的关键词。同一时间只能有一次校验，进行中再发起时 MUST 提示正在校验，不开始新的一次。

#### Scenario: 书源自带关键词
- **WHEN** 书源甲的 `ruleSearch.checkKeyWord` 是「三体」，书源乙没有设置，用户用默认关键词校验这两个书源
- **THEN** 书源甲用「三体」搜索，书源乙用「我的」搜索

### Requirement: 检查步骤
每个书源 SHALL 依次执行：搜索 → 第一个搜索结果的详情 → 目录 → 目录里第一个不是卷名的章节的正文（下一章是再后面一个不是卷名的章节）。文件类书源查到详情为止。任何一步出错就停止；四步都成功时为通过。没有搜索地址的书源 MUST NOT 发出请求。每个书源从开始执行算起最多 180 秒；同时最多校验 16 个书源。

#### Scenario: 正文为空
- **WHEN** 书源搜索、详情、目录都正常，正文规则取到空内容
- **THEN** 这个书源校验失败，原因是正文为空

### Requirement: 标记结果
每个书源开始校验时 SHALL 先从 `bookSourceGroup` 里去掉上次校验标上的分组（名字里带「失效」的，以及下表里的全部分组），从 `bookSourceComment` 里去掉以 `// Error: ` 开头的段落（段落按空行分隔）。校验失败时 SHALL 按原因加上一个分组，并在注释最前面加上 `// Error: 原因`（原注释不为空时中间空一行）：

| 原因 | 分组 | 注释里的原因 |
|---|---|---|
| 没有搜索地址 | 搜索链接规则为空 | 搜索链接规则为空 |
| 搜索返回 0 本 | 搜索失效 | 搜索失效 |
| 目录为空 | 搜索目录失效 | 搜索目录失效 |
| 正文为空 | 搜索正文失效 | 搜索正文失效 |
| 超过 180 秒 | 校验超时 | 超时：超过 180 秒 |
| 书源 JS 出错、不支持的 JS 用法、不支持的宿主 API | js失效 | 错误原因 |
| 其它错误 | 网站失效 | 错误原因 |

其余分组和注释段落的内容、顺序 MUST 不变；改写后为空的字段去掉（空和没有一样）。结果 SHALL 在每个书源完成时写回书源，位置和启用状态不变；导出的书源带着这些标记。

#### Scenario: 失败后标记
- **WHEN** 书源的分组是 `常用`，注释是 `作者：甲`，校验时搜索遇到网络错误「连接被关闭」
- **THEN** 分组变成 `常用,网站失效`，注释变成 `// Error: 网络错误：连接被关闭`、空一行、`作者：甲`

#### Scenario: 再次校验通过后清除标记
- **WHEN** 上面的书源再次校验并通过
- **THEN** 分组变回 `常用`，注释变回 `作者：甲`

#### Scenario: 搜索无结果
- **WHEN** 书源用关键词「我的」搜索返回 0 本
- **THEN** 加上分组「搜索失效」，注释最前面是 `// Error: 搜索失效`

### Requirement: 进度与停止
校验 SHALL 在后台进行，书源列表上方显示已完成数和总数；离开书源页面 MUST NOT 中断校验，回到页面时显示当前进度。用户 SHALL 可以停止：没完成的书源不再执行，也不改动它们，已完成的结果保留。

#### Scenario: 中途停止
- **WHEN** 校验 100 个书源，完成 30 个时用户停止
- **THEN** 这 30 个书源带着校验结果，其余 70 个和校验前一样
